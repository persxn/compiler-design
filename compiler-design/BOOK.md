Promise: given any usual lab-exam question, the reader writes the program from a blank file, builds it, runs it and explains every line to the examiner; given any usual written-paper problem, they work it by hand and check the answer with a program from this book.
Kind: system
Running project or case: the statement `pos = init + rate * 60;` is traced through every phase in chapter 1 and comes back in every chapter. Beside it, the reader builds a mini compiler for Tiny, a small language of assignments, + - * / and parentheses (if and while from chapter 9): a hand-written C scanner (ch 2), a Flex scanner (ch 4), a recursive-descent parser (ch 6), a Yacc parser (ch 8), a three-address-code generator (ch 9), then an optimiser and code generator (ch 10), all joined in 10.8.
Pictures: the compiler is an assembly line of stations, each handing its product to the next (breaks: the parser calls the scanner for one token at a time, so stations run interleaved, and the symbol table is shared by all); a parser's stack is a stack of plates where you only touch the top (breaks: an LR parser reads states, not just symbols); a DFA is a board game where each square says where each input card sends you (breaks: an NFA lets you stand on several squares at once); the symbol table is the compiler's notebook (breaks: real ones have one page per scope).
